# File map: what each file and folder is for

## Top level
- `README.md`: short project introduction and how to start.
- `PROJECT_EXPLAINED.md`: the whole project explained simply, from problem to verdict.
- `FILE_MAP.md`: this file.
- `AGENTS.md`: the project rulebook for every person and AI tool (honesty rules, no leakage).
- `CLAUDE.md`: extra rules for Claude Code (plan first, run the reviewer, protected files).
- `tasks.py`: one command runner: `python tasks.py check | data | splits | baselines | gen | pipeline | train | explain | demo | paper-figures …`.
- `pyproject.toml`: Python project settings (ruff code-style rules, pytest settings).
- `requirements.txt` / `requirements.lock.txt`: packages to install; the lock file pins exact versions.
- `.gitignore`: files git must never upload (raw data, predictions, logs).
- `.gitattributes`: keeps split files byte-identical on every computer (line endings).

## `.claude/` (Claude Code settings)
- `settings.json`: Claude Code settings; turns on the guard hook.
- `hooks/guard_paths.py`: blocks edits to raw data, splits, metrics files and secrets.
- `agents/eval-auditor.md`: the independent reviewer that checks evaluation honesty.

## `.githooks/` and `.github/`
- `.githooks/pre-commit`, `check_protected.py`: refuse commits that touch protected files (tests, rules, decisions, results).
- `.github/workflows/check.yml`: GitHub runs lint and all tests on every push.

## `configs/` (settings, written before running)
- `datasets.yaml`: every dataset's source, licence, origin (real, simulated or unknown) and role.
- `channels_pamap2.yaml`, `channels_wesad.yaml`: which sensor channels are used from each wearable dataset.
- `baselines/lovdal.yaml`: injury models, their setting grids, seeds and the evaluation procedure.
- `baselines/pamap2.yaml`: activity-recognition models (CNN, GRU) and their grids.
- `fused_candidates.yaml`: the fused model's candidate parts and combiner grid.
- `gen/generators.yaml`: generator settings and grids, pass marks and the follow-up stage.

## `data/`
- `raw/`: original downloaded datasets (local only, never on GitHub).
- `processed/`: cleaned arrays made by code (local only); `lovdal_lockbox/` holds the locked runners.
- `splits/`: person-level train/validation/test splits, made once and sealed with checksums.
- `MANIFEST.csv`: a fingerprint (SHA-256) of every raw file, to prove the data never changed.
- `README.md`: what goes in each data folder.

## `docs/`
- `PROJECT_BRIEF.md`: what Review 1 promised and the project goals.
- `PLAN.md`: the pieces 0–10 and their order.
- `STATE.md`: current status, done work with evidence, open items.
- `DECISIONS.md`: every decision (D-001 to D-034), with reason and alternatives.
- `EVAL_PROTOCOL.md`: how everything is scored and the pass marks (fixed in advance).
- `DATASETS.md`: the dataset audit table and the rules per dataset.
- `DATA_CONTRACT.md`: the agreed data formats for Track A (injury logs) and Track B (sensors).
- `CLAIMS.md`: each claim, its evidence, and whether it is supported.
- `VIVA_NOTES.md`: simple explanations and likely viva questions with answers, per piece.
- `STUDY_GUIDE.md`, `PIECE2_EXPLAINED.md`: beginner study notes.
- `AI_LOG.md`: log of AI-assisted work (for the paper's AI-use statement).
- `SETUP_WINDOWS.md`: how to install the project on a Windows laptop.
- `REVIEW_2026-10-29.md`: the final review's findings.
- `FIX_GUIDE.md`: step-by-step fixes for the paper and report, plus the paused tasks.
- `TODO_DASHBOARD.md`: the dashboard plan (now done).
- `data_cards/*.md`: one fact sheet per dataset (generated by code).
- `handoff/`: task cards given to builder tools (WP-01 metrics, WP-02 bootstrap, WP-03 networks) and their template.

## `src/data/` (reading and protecting the data)
- `readers.py`: turns one raw file into Python objects (no cleaning).
- `audit.py`: dataset audit: facts and checks about every raw dataset.
- `hashing.py`: file fingerprints shared by audit, loaders and splits.
- `manifest.py`: checks that builders read exactly the audited raw files.
- `parallel.py`: runs per-file jobs on all CPU cores within free memory.
- `loaders.py`: loads Lövdal runner data for development runners only.
- `windows.py`: cuts PAMAP2 and WESAD recordings into 25 Hz, 128-step windows.
- `daily.py`: daily tables for SoccerMon and PMData (Track C).
- `reference.py`: Sport DB 2.0 heart rate, SIRP-600 and ziya07 tables.
- `splits.py`: makes the person-level splits once.
- `lockbox.py`: the only door to the 10 locked runners: opens only at the frozen commit and logs every opening.
- `datacards.py`: writes the dataset fact sheets.

## `src/eval/` (scoring)
- `metrics.py`: PR-AUC, ROC-AUC, calibration, alert level and net benefit.
- `bootstrap.py`: runner bootstrap intervals and paired comparisons.

## `src/models/` (injury and activity models)
- `data.py`: builds one round's data, scaled on its training runners only.
- `baselines.py`: constant risk, ACWR rule, logistic regression, and the leak canary.
- `fitters.py`: one fit function per tuned model (RF, CatBoost, GRU, Lövdal).
- `nets.py`: neural networks (CNN, GRU, LSTM, TCN) and their training loop.
- `tuning.py`: seeded random search and the "choose on validation" rule.
- `evaluate.py`: all numbers for one model in one round (validation picks the thresholds).
- `lovdal_method.py`: the published Lövdal bagged-XGBoost method, rebuilt.
- `run.py`: runs all piece-3 baselines (`python tasks.py baselines`).
- `fused.py`: the fused model (sequence part + tree part + combiner), 5 rounds.
- `final.py`: the final model and the one locked test.
- `track_c.py`: the small SoccerMon/PMData extra study.

## `src/gen/` (synthetic data)
- `models.py`: TimeGAN, WGAN-GP, TimeVAE and classic augmentation.
- `evaluate.py`: realism, usefulness (TSTR) and privacy checks for generated data.
- `run.py`: runs the generator stages with checkpoints and resume.

## `src/pipeline/` (IoT tiers)
- `tiers.py`: edge, fog and cloud as separate processes joined by queues.
- `bench.py`: the speed and bytes benchmark, tiered vs cloud-only.

## `src/xai/` (explanations)
- `explain.py`: SHAP, integrated gradients, attention, Grad-CAM and plain-language reasons.
- `checks.py`: the deletion, randomisation and stability tests.
- `run.py`: explains the fused model's 5 rounds.

## `src/dashboard/` (coach dashboard)
- `prepare.py`: prepares all dashboard data in advance (`python tasks.py demo --prepare`).
- `data.py`: loads saved outputs for the dashboard (never the locked runners).
- `lab.py`: the Training lab page: safe retraining on one development round.
- `app.py`: the 8 Streamlit pages (`python tasks.py demo`).

## `src/paper/` (paper and slides from results)
- `figures.py`: writes every paper number and table from the result files.
- `deck.py`: builds the Review 2 slides (`slides/review2.pptx`) from the result files.
- `compare.py`: the paired model comparisons (runner bootstrap).

## `tests/` (289 automated checks, `python tasks.py check`)
- `test_audit.py`, `test_manifest.py`, `test_loaders.py`, `test_windows.py`, `test_daily.py`, `test_reference.py`, `test_splits.py`: the data code.
- `test_lockbox.py`, `test_final.py`: the lockbox and the final test.
- `test_models.py`, `test_gen.py`, `test_pipeline.py`, `test_xai.py`: the models, generators, tiers and explanations.
- `test_dashboard.py`, `test_dashboard_pages.py`: the dashboard (every page renders).
- `test_repo_tools.py`: the repository tools and hooks.
- `handoff/test_wp01_metrics.py`, `test_wp02_bootstrap.py`, `test_wp03_nets.py`: tests for the builder-tool task cards (metrics, bootstrap, networks).

## `experiments/` (every run's record: config, run_info with commit and seeds, metrics.json)
- `audit/`: dataset audit runs.
- `repro/`: the fresh-copy reproducibility check.
- `baselines/`: piece-3 model runs.
- `fused/`: the fused model.
- `generators/`: synthetic-data runs.
- `explain/`: explanation runs.
- `tiers/`: the IoT benchmark.
- `comparisons/`: paired comparisons.
- `track_c/`: the extra study.
- `lockbox_dry_run/`: final-test rehearsal on development runners.
- `lockbox/`: the one locked test.
- `lockbox_access.log`: the record of every lockbox opening.

## `paper/` and `slides/`
- `paper/main.tex`: the IEEE paper draft.
- `paper/report.tex`: the project report.
- `paper/refs.bib`: references.
- `paper/generated/*.tex`: numbers and tables written by `figures.py` (do not edit by hand).
- `slides/review2.pptx`: the Review 2 deck (generated).
- `slides/PBL_1_AIOT.pdf`: the Review 1 slides.
- `slides/img/`: chart images for the deck.

## `backups/`
- Placeholder folder for backups (empty in git).
