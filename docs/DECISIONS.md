- D-018 | 2026-10-15 | SoccerMon (#8, subjective part only, CC BY 4.0) and PMData (#9) are secondary, exploratory datasets, never main injury evidence. Label rule (mirrors Lövdal): a pain report at most 21 days after the same person's previous report continues the episode, 22+ days starts a new one; an episode's first day is a positive event; a healthy event is a day with no report within 21 days before or after and more than 21 days from the start and end of the person's data; a first report within 21 days of the data start is not counted (it may continue an unseen episode); a day without a report counts as no pain (assumption); empty PMData reports ({}) are ignored; PMData p08 is excluded from injury tasks (missing injury file is not "no injuries"). Counts from data/processed/*/daily_meta.json: SoccerMon 27 episodes in 14 of 50 players; PMData 8 episodes in 6 of 15 labelled people | real self-reported pain on the same days as load and wellness, but body-map pain is not a diagnosis and the same pain is often reported on many days | counting every report as an injury (162 SoccerMon and 77 PMData reports are mostly repeats); using them as main evidence | Naman (approved with the piece-2 plan)
- D-019 | 2026-10-15 | Processing choices (piece 2). Loaders keep raw values: no scaling or imputation (fitted on training folds later). Daily tables (Track C): one row per person per day, UTC dates, missing days stay empty; PMData per-minute heart_rate.json not used. Sport DB heart rate: plausible = 30-220 bpm (0 = no signal), rate inferred ~1 Hz [VERIFY]. Every builder hashes the raw files it reads and stops if they differ from data/MANIFEST.csv. - D-021 | 2026-10-22 | Tuning and leakage rules for all model work, fixed before piece 3. (1) Scores and model list are fixed before any run (D-022); every listed model is reported. (2) Settings, alert level, calibration and early stopping are chosen inside each round on that round's validation runners only, never by averaging validation scores across rounds: one round's validation runners are another round's test runners (e.g. runner 20: validation in rounds 0, 2 and 4, test in round 1). The final model's settings are chosen on its own validation group (13 runners, D-017). (3) The Lövdal method is copied exactly, including its label-reading test scaling (main.ipynb cell 1, lines 53-57 and 263), only once, as a labelled reproduction check on stand-in runners 54-63 trained on 0-53; that score is never used to choose anything. Every comparison uses a label-free variant that scales each runner with their own earlier events only (training-runner statistics when the history is too short). (4) Our models: one scaler fitted on each round's training runners only; per-runner own-earlier-events scaling is allowed only as a setting chosen inside the round; never labels, never later days. (5) The model for the locked test is declared now: the fused model (piece 7). No model is promoted because it scored best on the development rounds; if a baseline beats the fused model, that is reported. (6) Every model gets the same pre-declared tuning budget per round. (7) Class balancing and resampling only on training runners. | tuning outside the test loop gives optimistic estimates (Varma & Simon 2006, doi 10.1186/1471-2105-7-91); choosing the best model on test data biases its score (Cawley & Talbot 2010, JMLR 11:2079-2107); preprocessing that sees test data is leakage (Kapoor & Narayanan 2023, doi 10.1016/j.patter.2023.100804) | one global setting by averaging across rounds; comparing with the paper's label-reading scaling; sending the best development model to the locked test | Naman (approved plan, 2026-10-22)
- D-022 | 2026-10-22 | Track A scoring and the piece-3 model list. HEADLINE: PR-AUC computed as average precision, mean ± SD over the 5 rounds, shown with each round's injury rate (the chance level). ROC-AUC alongside, for the paper comparison. ALERT LEVEL: smallest |sensitivity - specificity| on the round's validation runners (the Lövdal rule, main.ipynb cell 1 line 86), applied to that round's test runners. At that level: sensitivity, specificity, precision, false alarms per caught injury, alerts per 100 runner-days, MCC. CALIBRATION: Brier score, ECE with 10 equal-count bins, calibration slope and intercept; Platt scaling fitted on validation runners when calibration is needed. EXPLORATORY: decision curve (net benefit) on calibrated risks over 0.5-10 %. DROPPED: the 'recall at fixed precision' blank (precision depends on the injury rate; precision is still reported at the alert level). COMPARISONS: paired bootstrap resampling runners (with 5 rounds a two-sided Wilcoxon test cannot go below p = 0.0625). SEEDS: 0, 1, 2 (rule-based models run once). MODELS (all reported): majority class; ACWR-style 3-week rule (D-015); logistic regression, random forest and CatBoost on the day file (70 inputs) and on the week file (69 inputs); GRU on the day file; Lövdal bagged XGBoost (exact copy only as the D-021 reproduction check; label-free variant on the 5 rounds). Activity (PAMAP2): small 1D-CNN and GRU, macro-F1. LIMITATION stated with every result: the authors removed healthy days near injuries, so alert rates are not real daily rates. | PR-AUC suits rare events (Saito & Rehmsmeier 2015, doi 10.1371/journal.pone.0118432) and average precision avoids invalid PR interpolation (Davis & Goadrich 2006, doi 10.1145/1143844.1143874); the paper's rule allows a direct comparison and does not depend on the injury rate; calibration is essential and rarely reported for sports-injury models (Van Calster et al. 2019, doi 10.1186/s12916-019-1466-7; Bullock et al. 2022, doi 10.1007/s40279-022-01698-9); net benefit shows usefulness (Vickers & Elkin 2006, doi 10.1177/0272989X06295361; Vickers, Van Calster & Steyerberg 2016, doi 10.1136/bmj.i6) | fixed-precision target as the main alert score; accuracy; Wilcoxon as the main test | Naman (approved plan, 2026-10-22)
