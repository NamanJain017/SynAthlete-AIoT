- D-017 | 2026-10-15 | Person-level split design (data/splits/, created once on 2026-10-15 from commit 8e5b360, seed 0). Lövdal: lockbox = runners 64-73, the paper's test set (50 injuries / 2,994 healthy day events; called "the 10 newest runners", not a time-based or prospective test); development = runners 0-63 in 5 test groups (StratifiedGroupKFold, built once on the day file and used unchanged for the week file and fusion); each fold's validation group comes from the remaining development runners; final model: train 51 / validation 13 (development group 0) / test = lockbox; paper_split (train 0-63 / test 64-73) only for rebuilding the Lövdal method at the end. Balance rule: each test group's injuries within ±20 % of the mean, else stop and ask; the group counts were previewed before this rule was written, so it is a sanity check, not a pre-registered criterion. HEADLINE result = mean ± spread over the 5 development test groups (64 runners, 533 day-file injuries); the lockbox is opened ONCE, at the evaluation freeze (git tag eval-freeze), as the final check, and both are reported. Not before, even if Review 2 comes first (Review 2 then shows development results with the lockbox sealed). The piece-3 pipeline check of the Lövdal method uses stand-in runners 54-63 (trained on 0-53), never 64-73. The list of compared models is fixed in piece 4 before comparing, and every model is reported. Lockbox injury rate is never used for calibration. Locked runners are saved apart (data/processed/lovdal_lockbox/) and read only via src/data/lockbox.py, which needs the eval-freeze tag and logs every opening. Disclosure: lockbox rows were part of dataset-level audit statistics (counts, missingness) in piece 1; no model has been trained or scored on them. Other files: PAMAP2 4 test groups of 2 (109 always in training); WESAD 5 groups of 3; Sport DB 2.0 GroupKFold(5) by subject folder (skating recordings kept together); SoccerMon leave-one-player-out (50); PMData leave-one-person-out (15; p08 excluded: injury file missing); SIRP-600 80/20 by rows, demo only | splits by person stop leakage; keeping the paper's exact test set allows a direct comparison; the 5 groups test about 10x more injuries than the lockbox (533 vs 50) so the headline is more precise, and the untouched lockbox guards against tuning to the development groups | lockbox-only headline (50 injuries, noisy); random 5-fold over all 74 runners (no clean comparison with the paper); running the paper's method on 64-73 early (uses the final test, and their test scaling reads test labels) | Naman ("1 yes 2 yes 3 A as main result with B as final check")
- D-018 | 2026-10-15 | SoccerMon (#8, subjective part only, CC BY 4.0) and PMData (#9) are secondary, exploratory datasets, never main injury evidence. Label rule (mirrors Lövdal): a pain report at most 21 days after the same person's previous report continues the episode, 22+ days starts a new one; an episode's first day is a positive event; a healthy event is a day with no report within 21 days before or after and more than 21 days from the start and end of the person's data; a first report within 21 days of the data start is not counted (it may continue an unseen episode); a day without a report counts as no pain (assumption); empty PMData reports ({}) are ignored; PMData p08 is excluded from injury tasks (missing injury file is not "no injuries"). Counts from data/processed/*/daily_meta.json: SoccerMon 27 episodes in 14 of 50 players; PMData 8 episodes in 6 of 15 labelled people | real self-reported pain on the same days as load and wellness, but body-map pain is not a diagnosis and the same pain is often reported on many days | counting every report as an injury (162 SoccerMon and 77 PMData reports are mostly repeats); using them as main evidence | Naman (approved with the piece-2 plan)
- D-019 | 2026-10-15 | Processing choices (piece 2). Loaders keep raw values: no scaling or imputation (fitted on training folds later). Lövdal: steps ordered oldest -> newest (day-file suffix order kept, week file reversed; verified on the data and pinned by tests); rest-day mask where all three perceived values are -0.01 (value kept). Sensor windows (configs/channels_*.yaml): 25 Hz, 128 steps, stride 64; PAMAP2 gaps up to 0.5 s (IMU) and 2 s (heart rate) interpolated, longer gaps make samples invalid; heart rate (~9 Hz) is interpolated; 100 -> 25 Hz by anti-aliased decimation; WESAD wrist only, BVP and ACC by polyphase resampling, EDA and TEMP interpolated from 4 Hz, labels by nearest sample; a window is kept only if all its samples are valid and it, plus 10 steps on each side, carries one allowed label. Daily tables (Track C): one row per person per day, UTC dates, missing days stay empty; PMData per-minute heart_rate.json not used. Sport DB heart rate: plausible = 30-220 bpm (0 = no signal), rate inferred ~1 Hz [VERIFY]. Every builder hashes the raw files it reads and stops if they differ from data/MANIFEST.csv. DATA_CONTRACT updated (Track C, Lövdal order, lockbox folder) | reproducible, leakage-free processing; every choice that could change a result is written down | scaling in the loader (leaks test statistics); keeping mixed-label windows | Naman + Claude (piece-2 plan)
- D-020 | 2026-10-15 | One-time exception to "splits are created once": data/splits/pamap2_folds.json and wesad_folds.json are re-made before any model is trained.
